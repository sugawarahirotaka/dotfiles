# Markdownの組み立て方

Markdownは文章の論理を見える形にするために使う。
情報を細かく砕くための装飾として使わない。

## 長さに合わせて構造を選ぶ

- 一から三段落で済む回答には、タイトル、見出し、目次を付けない。
- 異なる二つ以上の話題を探す必要がある場合だけ見出しを付ける。
- 長い独立文書では、読み手が途中から読めるように見出しを置く。見出し階層は原則として三階層以内にする。
- 一文ごとに改行しても、同じ段落の文の間には空行を入れない。段落、リスト、表、コードブロックの前後には空行を置く。

## 段落、リスト、表を使い分ける

- 因果、対比、譲歩、主張と根拠の関係は段落で書く。
- 同じ役割を持つ選択肢、条件、例、確認項目は箇条書きにする。
- 順序、優先度、手順がある場合だけ番号付きリストを使う。
- 一項目だけのリストを作らない。各項目の文法と粒度を揃える。
- `- **性能**：...`のような太字ラベル付き箇条書きを既定形にしない。関係のある内容は段落へ戻し、複数軸で比較できる内容は表にする。
- 表は、同じ対象を二つ以上の軸で比較するときに使う。一列だけの表、長文を詰めた表、ページ配置のための表は使わない。
- 表の前に何を比較するかを一文で示し、表の後に読み取るべき差を文章で述べる。

## 強調を論理の要所へ限る

- 太字は、初出の定義、誤読を防ぐ否定、読み飛ばされると結論が変わる語句に限る。
- 各見出し、各リスト項目、各数値を機械的に太字にしない。
- 引用ブロックは引用または改善前後の例に使う。通常の結論を囲むために使わない。
- コールアウトは、重大な警告、前提、再現条件など、本文から分離する理由がある場合だけ使う。
- 絵文字、飾り罫線、連続する短い決め台詞を既定では使わない。

## 技術要素を正確に示す

- コード識別子、コマンド、ファイル名、設定値はインラインコードで示す。
- 複数行のコード、差分、ログ、設定ファイルは言語名付きのコードブロックにする。
- 数式は必要な式だけを示し、直前または直後に、その式から何がわかるかを書く。
- リンクのラベルには、リンク先の内容がわかる語を使う。「こちら」だけにしない。
- 図には、何を見るべきかを本文またはキャプションで示す。画像だけを置いて説明を終えない。

## 表示前に確認する

- 見出しだけを追って、文書の対象と順序がわかるか。
- リストを段落に戻したほうが、項目間の関係が明確にならないか。
- 表のセルが文章の置き場になっていないか。
- 太字を半分に減らしても意味が変わらないなら、減らしたか。
- Markdown要素の前後に空行があり、CommonMarkとして崩れないか。
